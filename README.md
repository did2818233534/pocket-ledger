# 小账 · 安卓本地记账

安卓手机离线记账，SQLite 保存手机账目；两部手机通过电脑双向合并多个用户的账本，使用局域网或可选的内置 Tailscale，使用可直接阅读和复制的 JSON 文件保存。账本不上传云端存储；Tailscale 的账号协调和加密中继使用其网络服务。

## 目录

| 用途 | 本机位置 |
| --- | --- |
| Git 源码 | `/home/guga/myself/project/pocket-ledger` |
| 电脑服务程序 | `/opt/pocket-ledger/server.py` |
| 独立数据目录 | `/opt/pocket-ledger/data/` |
| 月度账目 | `/opt/pocket-ledger/data/YYYY-MM.json`（如 `2026-10.json`） |
| 同步版本和月份索引 | `/opt/pocket-ledger/data/sync.json` |
| 配对配置 | `/opt/pocket-ledger/data/config.json` |
| 旧数据库 / 单文件 JSON 备份 | `/opt/pocket-ledger/backups/` |
| 手机安装包（不提交 Git） | `dist/小账-1.3.0.apk` |

电脑运行程序及数据不依赖源码目录。用户级 systemd 配置保存在 `~/.config/systemd/user/pocket-ledger.service`，启动的是 `/opt/pocket-ledger/server.py`。已为本机用户开启 linger，使服务可以开机启动而无需桌面登录。

## 使用

1. 手机安装 APK，支持 Android 8.0 及以上。本机实体手机已覆盖安装，不会卸载应用或清除账目。
2. 电脑服务依赖系统 Python 和 `python3-zeroconf`，本机已经具备。其他电脑先安装发行版的 `python3-zeroconf` 包，再运行 `bash desktop/install-service.sh`。
3. 安装脚本把程序部署到 `/opt/pocket-ledger`，保留已存在的数据及密钥，更新并启动开机服务。首次创建 `/opt` 下的目录可能需要 sudo；不把密码写入脚本或配置。
4. 运行 `python3 /opt/pocket-ledger/server.py --pair` 查看地址和配对密钥。
5. 手机与电脑连接同一局域网，在“同步”页填写 `guga.local` 或电脑局域网 IPv4 地址，以及 64 位配对密钥，点击“保存并开启后台检查”。本机手机已经配对，无需再次填写。

手机每次新增或编辑账目，**先写入本地数据库，再后台尝试同步**。电脑不在线、网络错误或同步失败不会弹窗，也不会影响保存；下次发现电脑、每分钟检查或手动同步会重试。删除同样同步到电脑。

“暂停后台检查”只暂停持续的 mDNS 发现与一分钟定时检查。只要已经配对，每次保存仍会尝试同步，也能手动点击“立即同步”。手动同步失败会在同步页显示原因，便于排查。

## 多个用户、多部手机

两部手机安装同一个 v1.3.0 APK，配对同一台电脑（相同密钥）。手机不绑定用户：任意一部手机都能为任一用户记账，也能编辑、删除任意人的记录。

- 账本和统计顶部的“账本用户”在输入框下方展开，可勾选一个或多个用户；支持全选，至少保留一个选择。选中的范围同时作用于明细、四个时间段的环形图和柱状图。
- 只勾选一位用户时，新支出默认记在该用户名下；勾选多位时合并查看，新增默认沿用上次记账用户，下方会明确提示。
- 编辑支出时，“这笔支出记给谁”通过单选下拉菜单调整归属；每笔支出只属于一位用户。保存后该用户成为当前手机下一笔记账的默认用户。
- 用户下拉菜单底部可直接添加用户，“同步 → 记账用户”也可添加和修改名字，通过同一用户 ID 添加后，名字和头像会同步到相应手机。用户数量不限于两人，新账本初始只有“用户一”，可改名或继续添加。
- 用户是账本内的分类身份，没有独立密码或隐私隔离。两部手机上的查看范围和默认记账用户互不影响。
- 原有账单升级后默认归到“用户一”，账单 ID、金额和时间保留。可在编辑时调整归属。

电脑是同步中转，两部手机不直接互连。电脑离线时，两部手机各自保存；再次连接后上传本地更改、下载另一部手机的记录，每部手机只保留本机已添加用户的账本。另一部手机收到更新的时间取决于它下一次同步，不是即时推送。

首次启用新版共享协议后，旧版客户端会被拒绝同步，防止全量覆盖共享账本；请把两部手机都升级后使用。第二部手机首次同步不会用空账本清除电脑上的记录。

## 用户 ID、按用户同步和头像

- **新建用户**生成固定 UUID。同名用户也可能是不同的人；匹配身份只看 ID，改名不会改变 ID。
- 在“同步 → 本机同步的用户”可查看、复制 ID。另一部手机在用户下拉菜单或同步页选择“通过 ID 添加已有用户”，粘贴完整 ID 后同步。
- **只下载本机已添加 ID 的名字、头像和账单**。只添加用户 A 就不获取用户 B 的资料；再次添加 B 才下载 B。勾选框控制查看/统计范围，不改变同步范围。
- ID 尚未在电脑出现时，显示“等待获取用户”，不会创建同名假用户或覆盖远端名字。让原手机先同步到电脑后再试。
- “从这部手机移除”清理该用户在本机的副本并停止同步，保留电脑和其他手机的账单，可再次通过同一 ID 添加。为避免丢失离线修改，移除前需完成同步；至少保留一位用户。
- 两部手机都需要 v1.3.0。旧共享协议被拒绝，避免旧客户端继续全量下载。

身份资料只保存当前值和更新时间：`id`、`name`、`nameAt`、`avatar`、`avatarAt`。名字和头像分别按时间戳比较，新的覆盖旧的；同时间戳用当前值排序打破平局，确保重试顺序不影响最终结果。用户资料不再使用逻辑版本或设备标识作为同步依据，也不维护历史名字、历史头像或身份变更日志。旧版资料第一次升级时，已有名字以升级时刻初始化时间戳。

点击“添加头像 / 更换头像”从手机选择照片，应用在内存中居中裁成 192×192 JPEG，去掉原图元数据。只将当前压缩头像和设置时间写入用户记录，电脑 `sync.json` 中也只保存当前头像；更换后覆盖当前字段，不创建旧图文件或版本目录。移除头像保存空头像及新的时间戳，防止旧图片再次同步回来。相册原图不受影响。名字和头像的时间戳互不覆盖，因此一端改名不会回退另一端的新头像。

配对密钥仍用于连接同一台电脑；用户 ID 用于选择同步资料，不是单独的用户密码。头像与账目共用已有局域网 / Tailscale 通道，每次请求和响应仍各限制 4 MiB。

## 可选的 Tailscale 远程同步

不登录、不启用远程同步时，应用不启动 Tailscale，局域网功能照常使用。

1. 电脑安装并登录 Tailscale，保留现有的小账同步服务。本机已有客户端，无需重装或改变其登录配置。
2. 手机打开“同步 → 远程同步 → 开启 Tailscale 远程同步”，等待登录链接后点击“前往 Tailscale 登录”。官方认证在手机浏览器完成，返回小账即可；不在电脑打开窗口。
3. 登录电脑所在的 tailnet。内置客户端以独立节点 `pocket-ledger` 出现在网络中；如果网络要求审批，请在管理页面批准该节点。
4. 在小账的设备列表中选择运行小账服务的电脑。电脑离线仍可选择并保留地址，网络访问策略须允许该节点访问电脑 TCP 47831。
5. 配对密钥仍是必需项。已配对用户不必重新输入；身份和数据完整性继续通过请求、响应 HMAC 验证。

每次同步先尝试局域网，无法完成后才尝试内置 Tailscale。`.local` / mDNS 只用于局域网，远程连接使用选择的 Tailscale IPv4。成功状态显示本次使用的连接方式。保存、编辑、删除和一分钟后台检查都复用同一策略；自动失败不弹窗。

“关闭远程同步”停止内置节点但保留手机私有目录中的登录状态，再开启可恢复；“退出 Tailscale 账号”联网注销当前节点，之后重新登录。注销失败会明确提示，不能当作已注销。退出和关闭都不影响本地账目及局域网配对。电脑端程序接受 tailnet 来源时还要求请求到达本机 tailnet 地址，不向公共互联网开放无需认证的同步入口。

实现：使用上游 `tailscale.com/tsnet v1.104.1`，Go / gomobile 编译为 Android 原生库，Java 提供网络接口信息和登录 UI。没有单独启动外部 Tailscale App，也不使用 Android VpnService 接管其他应用流量。实际安卓 ABI 为 arm64-v8a 和 x86_64；不支持仅 32 位的手机。Tailscale 身份数据在 `getNoBackupFilesDir()/tailscale`，不进入账本导出或系统备份。上游及实际依赖的许可包含在应用“关于内置 Tailscale → 开源许可”。

手机进程被强行停止、系统休眠或后台限制仍可能暂停自动检查，重新打开小账可恢复。远程同步要求电脑开机联网，不能唤醒已关机的电脑。

## 界面和统计

- **账本**：本月、本周总额，四类支出摘要，按月查看流水；点击记录修改或删除，右下角添加。
- **统计**：当月、本周、近 7 天、近 30 天；分类百分比环形图、每天支出柱状图、日均和自付金额。
- **同步**：连接状态、最近成功时间、待同步提示、手动同步、后台检查开关、配对和 JSON 导出。

支出属性为“日常生活、额外支出、报销垫付、借出赠与”。属性菜单紧贴输入框下方展开，包含图标、说明和选中标记；点击外部或返回键先收起菜单。支持方向键选择和 Escape 收起。

总支出包括全部属性，自付支出排除报销垫付。“报销垫付”和“借出赠与”是支出属性，不另外管理报销到账或借款回收状态。金额以整数分保存，避免浮点金额误差。

统计按手机本地日历日期计算，本周从周一开始，近 7 / 30 天包含今天。当月、本周统计截至今天；未来日期记录保存在对应月份流水中，未计入当前统计。日均包含范围内所有自然日，包括零支出日。

- 属性菜单展开时先收起菜单。
- 编辑页面有未保存修改时，确认放弃才关闭；取消确认会保留输入。

## mDNS 和同步机制

电脑使用 `python-zeroconf` 发布 `_pocket-ledger._tcp.local.` 服务，本机主机名为 `guga.local`，端口 TCP 47831。手机使用 Android NSD 发现服务，解析其地址，再验证 TXT 中绑定地址和端口的 HMAC 签名；匹配已保存的配对密钥后才更新电脑地址并同步。电脑 IP 变化时会重新发布，手机每分钟也重新检查。原先的自定义 UDP 47832 广播已移除。

首次配对仍需要密钥。mDNS 负责发现，不代替身份校验；密钥不会通过发现消息发送。HTTP 请求与响应也使用 HMAC-SHA256，要求两端时间差在 120 秒以内。

局域网直连支持 RFC1918 私有 IPv4。远程同步使用 Tailscale 的 100.64.0.0/10 节点地址，底层可经互联网直连或加密中继。若有防火墙，需允许可信局域网的 TCP 47831 和 mDNS UDP 5353。访客 Wi-Fi、AP 隔离或 VPN 可能影响发现；保存的电脑地址仍可作为连接入口。`.local` 地址能否直接解析取决于手机系统，服务发现会使用解析出的局域网 IPv4 地址。

**局域网 HTTP 内容未加密**，请使用可信网络。配对配置和账本文件限制为当前用户读写。手机关闭了系统自动备份。

两部手机均可编辑，电脑按账单 UUID 合并。用户身份与设备 ID 分开保存。每次本地修改递增逻辑时钟；收到远端数据后推进本地时钟。账单按 `(version, actor)` 选择较大版本，同一版本以设备 UUID 排序打破平局，结果不依赖请求到达顺序。同步中同时发生的本地修改不会被旧响应覆盖。

同时离线修改同一笔账单时，只保留一个确定的版本，不做字段级合并，也没有历史版本恢复界面；逻辑版本不代表真实时间的先后。删除用持久化 `deleted: true` 标记参与合并，避免旧副本重传后复活；更高版本的后续编辑仍可覆盖删除。不要手动清除删除标记。电脑不是历史版本归档。

同步为带签名的全量双向交换，请求与响应各限制 4 MiB。超限时账目仍在本地，手动同步可查看失败状态；按月存文件不消除这个传输上限。

Android 后台使用 `connectedDevice` 前台服务与常驻通知。省电、Doze、厂商限制或强行停止会影响定时精度。手机重启后需要打开应用恢复检查；电脑通过 systemd 独立开机运行。

参考：[Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd)、[python-zeroconf](https://python-zeroconf.readthedocs.io/en/latest/api.html)。

## 复制和迁移电脑数据

日常数据按月份拆分，全部放在同一个 `data` 目录：

```text
data/
├── config.json       # 配对配置
├── sync.json         # 同步版本和月份索引
├── 2026-09.json      # 9 月支出（有记录才生成）
└── 2026-10.json      # 10 月支出
```

每个月的文件只包含该月账目，为 UTF-8、缩进排版的 JSON。金额单位为分，按支出时间的本地日历月份归档，而不是按同步日期。跨月修改会移动到对应月份；删除后仍保留该月文件中的删除标记，界面和统计会排除这些记录。未改变的月份不会重写。

`sync.json` 记录设备版本、用户列表、当前名字/头像及各自更新时间、月份索引和旧设备迁移状态，不重复存账目；`config.json` 保存配对密钥。迁移时应一起复制，不能只复制某个月的文件。

1. 在旧电脑执行 `systemctl --user stop pocket-ledger`。
2. 复制整个 `/opt/pocket-ledger/data/` 到新电脑的同名目录；目标服务应处于停止状态，先备份目标已有数据，避免误覆盖。
3. 确认目标服务用户拥有目录读写权限，再启动服务。
4. 保留原 `config.json` 后，手机无需重新配对；mDNS 会发现新电脑地址。旧电脑应停用服务，避免两台电脑同时使用同一份配对身份。

也可以用 `python3 /opt/pocket-ledger/server.py --data /其他目录` 指定数据目录。手动查看 JSON 没有限制；迁移或修改文件时先停止服务。

JSON 文件使用同目录临时文件、fsync 和原子替换，并串行处理并发请求。跨月写入前会先保存隐藏的 `.pending-sync.json` 事务记录，完成后删除；中途断电或写入失败时，重启或下次访问会恢复完整操作，完成前不返回同步成功。这个临时文件不是日常存储格式，也不要在恢复前手动删除。

旧版 SQLite 或单个 `ledger.json` 会自动迁移成月度文件，原文件归档到 `/opt/pocket-ledger/backups/`；本机月度迁移已完成，账目、版本和配对配置均核对一致。v1.2.0 首次同步会自动转换成共享账本协议，保留原配对配置与账单；旧版手机必须升级。每月文件仍为 JSON。

这只是电脑副本的可迁移存储。手机可导出 JSON，但当前没有手机 JSON 导入/恢复界面；卸载手机应用前请先导出。

## 运维和更新

```bash
systemctl --user status pocket-ledger
journalctl --user -u pocket-ledger
python3 /opt/pocket-ledger/server.py --pair
python3 /opt/pocket-ledger/server.py --export /绝对路径/账本备份.json

# 更新部署，不覆盖 data 目录
bash desktop/install-service.sh

# 停止 / 恢复服务
systemctl --user stop pocket-ledger
systemctl --user start pocket-ledger
```

调试时保留手机 USB / ADB 连接以及两端正式服务，只清理临时测试进程和测试记录；不在电脑桌面弹出调试窗口。

## 开发和验证

仓库：`git@github.com:did2818233534/pocket-ledger.git`，分支 `main`。`.gitignore` 排除构建缓存、APK、截图、数据库、配对配置、签名文件和本地工具路径。

```bash
# 首次构建内置 Tailscale（Go、gomobile 和 Android NDK）
source /opt/pocket-ledger/toolchain/env.sh
bash build-tailscale.sh

# 使用已有 SDK 构建 APK，无需 Gradle
bash build-apk.sh

# 标准 Gradle 构建
GRADLE_USER_HOME=/opt/gradle-cache JAVA_HOME=/opt/android-studio/jbr \
  /opt/gradle/bin/gradle assembleDebug lintDebug --no-daemon

python3 -m unittest discover -s tests -v
node --test tests/model.test.js
```

### 金额计算器

金额框支持 `+ - * /`（也支持 `× ÷`）和嵌套括号，例如 `(480+20)*2`。按回车、切换到下一项、点击空白或等号会计算结果，保存时也会校验并计算。按通常的运算优先级计算，最终结果四舍五入到分；除以零、未完成的算式或非正金额不会保存。金额框下方提供运算符和括号按钮。

### 两级备注与统计

每笔支出可填写一级备注（例如“吃饭”，最多 60 字）和二级备注（例如“牛肉面”，最多 200 字），均为选填。已有备注保留为二级备注，一级备注初始为空，不会删除旧账单。两级备注随账单同步到电脑的每月 JSON。

统计页可切换支出属性、一级备注和二级备注，沿用选中的用户及当月/本周/近 7 天/近 30 天范围。一级备注按名称合并，不区分支出属性；二级备注按名称合并，不区分一级备注和支出属性。空备注单独列为“未填写”。环形图展示各组金额、占比及笔数，每日柱状图继续展示范围内的每日总支出。

数据库升级到版本 5；同步协议保留版本 4，新增可选字段 `primaryNote`。电脑服务需同步更新以持久保存新字段。旧客户端上传不含该字段的修改时，更新后的服务保留已存一级备注；清空一级备注通过显式空字符串同步。建议所有手机更新后再编辑两级备注。

### 支出日期

支出日期精确到天，不再记录时分。可直接填写 `YYYY-MM-DD`（也接受 `/`、`.` 分隔），或点击“滚动选择”滑动年、月、日。滚轮自动处理闰年和每月天数，取消或系统返回不会修改日期。

数据库版本 6 会直接去掉已有账单的时分；电脑服务启动时也会将每月 JSON 的旧时间转换为 `YYYY-MM-DD`。金额、备注、用户及同步版本不变。旧格式同步输入会统一转换为日期，防止时分重新进入账单。其他手机也需更新以使用日期选择和读取新的纯日期格式。
